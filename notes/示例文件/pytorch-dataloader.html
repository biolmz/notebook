PyTorch Dataset 与 DataLoader 拆解

2025-11-08 机器学习 PyTorch，数据管道

看教程的时候觉得 Dataset 和 DataLoader 很好懂，一上手就卡在三处： __getitem__ 到底该返回什么、collate_fn 什么时候要自己写、 num_workers 为什么在 Windows 上会挂。这篇把这三处逐个试一遍。

最小可用的 Dataset

Dataset 只用满足两件事：__len__ 给出长度， __getitem__ 给出第 i 个样本。返回什么完全由你定， 关键是后面 collate 那一步能不能把一列样本拼成一个 batch。

In [3]
import torch
from torch.utils.data import Dataset, DataLoader

class PeptideDataset(Dataset):
    def __init__(self, seqs, labels):
        self.seqs = seqs
        self.labels = labels

    def __len__(self):
        return len(self.seqs)

    def __getitem__(self, i):
        # 这里只做“取一条”，不做 padding、不做转 tensor
        return self.seqs[i], self.labels[i]
Out[3]
>>> ds = PeptideDataset(["ACDEF", "GGGK"], [1, 0])
>>> len(ds), ds[0]
(2, ('ACDEF', 1))

默认 collate 能拼什么

DataLoader 拿到一批样本后，默认会调用 torch.utils.data.default_collate： 数字和等长 tensor 会直接堆成 batch，等长序列转成「一批字符串」也能过。 但只要序列长度不一致，默认 collate 就会报错，因为 tensor 的每个维度必须等长。

In [5]
from torch.nn.utils.rnn import pad_sequence

def collate(batch):
    seqs, labels = zip(*batch)
    idx = {aa: k for k, aa in enumerate("ACDEFGHIKLMNPQRSTVWY", start=1)}  # 0 留给 padding
    tensors = [torch.tensor([idx[aa] for aa in s]) for s in seqs]
    x = pad_sequence(tensors, batch_first=True, padding_value=0)
    return x, torch.tensor(labels)

loader = DataLoader(ds, batch_size=2, shuffle=True, collate_fn=collate)
x, y = next(iter(loader))
print(x.shape, x.dtype, y)
Out[5]
torch.Size([2, 5]) torch.int64 tensor([1, 0])

这里有个容易忘的配套步骤：padding 到 0 之后， nn.Embedding 要设 padding_idx=0， 否则 pad 出来的位置也在更新梯度，还会污染后续的 mean pooling。

num_workers 的两个坑

现象原因处理
Windows 上 num_workers > 0 直接崩 子进程用 spawn 方式启动，会重新 import 主模块 训练代码写在 if __name__ == "__main__": 里面
多个 worker 取到重复的样本 每个 worker 各自有自己的随机数状态 在 Dataset 里用 torch.initial_seed() 派生种子，别用全局 random
In [9]
if __name__ == "__main__":            # Windows 上必须这样包起来
    loader = DataLoader(ds, batch_size=64, shuffle=True,
                        num_workers=4, pin_memory=True,
                        persistent_workers=True)
    for epoch in range(3):
        for x, y in loader:
            pass                          # 先只测数据管道，不接模型

实测下来，这个数据集（2 万条肽、平均长度 12）在 num_workers=0 时 一个 epoch 大概 1.8 s，num_workers=4 降到 0.6 s， 再往上加收益就不明显了 —— 瓶颈已经不在读数据上。

调数据管道的时候先单独跑 DataLoader，不接模型。这样测出来的时间才是数据管道本身的开销。

小结

  • __getitem__ 只管取一条，拼接逻辑放 collate_fn，两件事别混在一起。
  • 变长序列必须自己写 collate，顺手把 padding_idx 设好。
  • Windows 上用多进程，训练入口一定要包在 if __name__ == "__main__": 里。
